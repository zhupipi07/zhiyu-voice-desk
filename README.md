# 智语外呼 · 浏览器资审通话

测试者在本机浏览器扮演商家。百炼 `qwen-audio-3.1-realtime-flash` 作为 AI 资审专员主动开场，向 Node.js 查询合成申请单的材料要求，处理插话并继续告知。程序通过 WebRTC 收发语音，运行需要麦克风、可访问百炼的网络，以及北京地域的 API Key 和对应的 Workspace ID。

## 在本机接通第一通电话

安装 Node.js **24 或更新版本**。应用使用 Node 内置的 SQLite 和浏览器 WebRTC，启动前无需安装 npm 依赖。

1. 克隆并进入本仓库。在 Windows PowerShell 执行 `Copy-Item .env.example .env`，macOS 或 Linux 执行 `cp .env.example .env`。
2. 用文本编辑器打开本机的 `.env`。在 `DASHSCOPE_API_KEY=` 后填队内分发的百炼密钥，在 `DASHSCOPE_WORKSPACE_ID=` 后填**创建这把密钥时所选北京业务空间的 ID**。保存文件。服务只从后端读取密钥，修改这两个值后要重启。[获取北京地域 API Key](https://help.aliyun.com/zh/model-studio/get-api-key) · [百炼 WebRTC 接入](https://help.aliyun.com/zh/model-studio/audio-realtime-webrtc-access)
3. 在仓库目录执行 `npm start`，保持终端打开。用 Chrome 或 Edge 打开 [本机通话测试台](http://127.0.0.1:8765)。每位队员在自己的电脑启动一份，建议戴耳机以便测试插话。
4. 点击「开始模拟通话」并允许麦克风。接通后先听坐席开场。点击「挂断」保存本次结果；通话结束后可在转写旁点击「回听」检查坐席实际播放的片段。

## 队员试什么

| 操作 | 在测试台检查 |
|---|---|
| 核身前追问“我缺什么材料？” | 坐席询问身份，右侧仅显示核身状态。随后回答“我是青禾商贸”，应出现两项整改要求和成功的核身记录。 |
| 在第二项讲到一半时开口问“具体补哪一页？” | 旧播报停止，盖章页成为“已播部分”。坐席查询本案依据，答复后续讲剩余要点。第一项保留为“已播完整”。 |
| 追问“传到哪里？”“补了就一定通过吗？” | 业务查询返回模拟提交入口或重新审核说明。超出该单依据的问题转为待核实。 |
| 中途刷新，点击「继续上次通话」 | 同一标签页从后端恢复当前申请、核身状态和待讲项。另开一通电话从核身开始。 |
| 另起一通，核身时说“你打错了” | 页面显示“错号已结束”，停止播报告知。 |

页面显示服务未配置时检查 `.env` 文件名、北京空间和运行目录。百炼建连返回 401/403 时核对密钥、空间与模型权限，429 时核对限流和额度。使用的是本机回环地址；浏览器会在点击开始时申请麦克风权限。

## 进度和证据

每次测试保存为独立的模拟申请办理会话。业务库位于 `data/review.sqlite`。坐席的播放回录、模型转写、工具结果、打断位置对应的回复和材料进度保存在本机。页面用通话凭据读取本次会话。浏览器在本地音频输出处截取每次坐席回复，后端结合回录的有效音量、完整转写中的材料要点和播放中断状态判断“待讲 / 已播部分 / 已播完整”。“已播完整”描述浏览器侧的播出情况，商家是否理解需另行询问。刷新或掉线时保留已持久化的进度，证据不足的要点会重新说明。第一版使用合成单 POP-DEMO-018 和两项模拟材料，京麦沙箱、正式质检及赛方时延测评属于后续阶段。[完整架构](ARCHITECTURE.md)

## 开发验证

`npm test` 覆盖核身门槛、材料查询、错号、播放证据、重复事件、重连和数据库重启，并检查转发给百炼的模型 ID。检测到 Chrome 或 Edge 时还会启动无界面浏览器，使用本地 WebRTC 对端、模拟麦克风和测试音频自动跑一通电话。可用 `CHROME_BIN` 指定浏览器可执行文件。自动化测试不消耗百炼额度；模型的实际听辨、音色和端到端时延需使用队内凭据联测。
