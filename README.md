# 智语外呼 · 浏览器资审通话

本仓库提供运行源码、合成案例、[复现指南](docs/REVIEW-GUIDE.md)和[自测记录](SELFTEST.md)。授权评审材料包根目录的 `评审入口.html` 可播放 79 秒闭环实录、回听逐轮录音并查看技术方案和自测报告。企业知识表、通话原始文件及签章材料单独交付。

### 启动和选单

参赛运行默认关闭预录的“嗯”。本机和云端两种入口均直接回答商家，自测以商家停语到正文起声为声学参考，正式首字时延按赛方工具复核。

Windows 安装 Node.js 24 后可双击 `start.cmd` 进入 Qwen + WebRTC 网关。脚本安装锁定的依赖，使用系统中文声音生成核准话术，在本机启动服务。浏览器在 `http://127.0.0.1:8765` 打开。云端模式需要北京百炼凭据。其他平台可执行 `npm ci`、`npm start`；没有本地话术音频时，网关使用云端语音。需要对照百炼原生 WebRTC 接口时可显式指定 `npm start -- --direct`。

本机也支持 `start-local.cmd`。这个入口使用本地 Paraformer 识别、案卷工具分流和系统中文语音，适合评测离线资审任务。两个入口共用案卷、核身门槛、进度、双声道录音、待办及回执。先关掉另一个入口或改用空闲的 `PORT`。本地模式预热模型后显示监听地址。环境、版本和切换方式见[评审与复现指南](docs/REVIEW-GUIDE.md)。

在“评委抽一单”选择案卷。018 为授权链路和盖章页，027 为店名整改，035 直接写入京麦模拟书面意见，046 登记二次外呼，支持接通或再次未接转书面。后两条分支的书面办理和任务登记可在没有云凭据时演示。评委可在本机另存 `cases/applications.json`，修改商家、整改项、三级分类或次数，并用 `REVIEW_CASES_FILE` 指向副本。新会话绑定所选案卷。已建会话保留建立时的材料。

### 赛方知识、分流与评审材料

在仓库根目录执行 `python scripts/import-knowledge.py "赛方资料包.zip"` 后重启。导入器读取定稿的「场景汇总」及「高频QA」，将行号与原工作簿 SHA-256 存入本地 `data/knowledge.json`。新建合成申请按三级分类查询关单方式。缺少资料包的队员仍可运行原合成案例。核身后的问答会引用已审定可直接告知的条目，涉及内部操作口径、适用条件或原表矛盾时留下待核实事项。

- `npm run route -- --row 52 --submissions 2 --missed 1` 查询指定场景与次数的下一动作。省略参数可列出全表的默认路线。`--callback`、`--escalation`、`--exposure` 分别表示案卷已有主动回电、越级投诉、外部曝光依据。
- `npm run eval:quality -- --out data/review-export-01 --audio` 以只读方式扫描历史库，输出可离线打开的 `index.html`、逐通 JSON 和已有双方录音。每次导出使用新目录。页面可按轮次跳到 WAV 的播放位置。省略 `--out` 可只看汇总。模拟回执、实际播出、商家确认分别取证。
- `npm run eval:rsi` 生成回电表达与核身条件组合，用开发集比较四个策略，选定后运行留出回归。输出逐例错误与版本号。需要回滚时将 `.env` 的 `CALLBACK_POLICY` 改为 `callback-v1` 并重启。新通话绑定该版本，已建立的通话继续使用创建时的版本。
- 做断句对照时，可分别以 `REVIEW_TURN_MODE=smart_turn_v2` 和 `REVIEW_TURN_MODE=server_vad` 启动新通话。后者使用 450 毫秒静音断句。当前网关默认 `server_vad_750`，使用 750 毫秒静音，适合与语义断句对照停顿误切和响应速度。逐通 JSON 保存本次配置与连接事件。

测试者在本机浏览器扮演商家。百炼 `qwen-audio-3.1-realtime-flash` 作为 AI 资审专员主动开场，向 Node.js 查询合成申请单的材料要求，处理插话并继续告知。程序通过 WebRTC 收发语音，运行需要麦克风、可访问百炼的网络，以及北京地域的 API Key 和对应的 Workspace ID。

## 在本机接通第一通电话

安装 Node.js **24 或更新版本**。网关与本地模式通过锁定的可选原生 WebRTC 依赖收发音频，Windows 启动脚本会自动安装。

1. 克隆并进入本仓库。在 Windows PowerShell 执行 `Copy-Item .env.example .env`，macOS 或 Linux 执行 `cp .env.example .env`。
2. 用文本编辑器打开本机的 `.env`。在 `DASHSCOPE_API_KEY=` 后填队内分发的百炼密钥，在 `DASHSCOPE_WORKSPACE_ID=` 后填**创建这把密钥时所选北京业务空间的 ID**。保存文件。服务只从后端读取密钥，修改这两个值后要重启。[获取北京地域 API Key](https://help.aliyun.com/zh/model-studio/get-api-key) · [百炼 WebRTC 接入](https://help.aliyun.com/zh/model-studio/audio-realtime-webrtc-access)
3. 首次运行先执行 `npm ci`，然后在仓库目录执行 `npm start`，保持终端打开。用 Chrome 或 Edge 打开 [本机通话测试台](http://127.0.0.1:8765)。每位队员在自己的电脑启动一份，建议戴耳机以便测试插话。
4. 点击「开始模拟通话」并允许麦克风。接通后先听坐席开场。点击「挂断」进入办理结果页，可查看已讲完的材料、待跟进事项并回听通话片段。核身成功的通话会显示本地模拟库保存的书面意见和回执，同一申请的同一审核版本共用一张回执。刷新当前标签页可重新查看。

暂时无法联测时，启动本地服务后可直接查看[第二项中途挂断的结果示例](http://127.0.0.1:8765/?example=partial)。示例使用固定的合成进度，独立于实际通话记录，无需麦克风或百炼凭据。

## 队员试什么

| 操作 | 在测试台检查 |
|---|---|
| 核身前追问“我缺什么材料？” | 坐席询问身份，右侧仅显示核身状态。随后回答“我是青禾商贸”，应出现两项整改要求和成功的核身记录。 |
| 在第二项讲到一半时开口问“具体补哪一页？” | 旧播报停止，盖章页成为“已播部分”。坐席查询本案依据，答复后续讲剩余要点。第一项保留为“已播完整”。 |
| 追问“传到哪里？”“补了就一定通过吗？” | 业务查询返回模拟提交入口或重新审核说明。超出该单依据的问题转为待核实。 |
| 中途刷新，点击「继续上次通话」 | 同一标签页从后端恢复当前申请、核身状态和待讲项。另开一通电话从核身开始。 |
| 另起一通，核身时说“你打错了” | 页面显示“错号已结束”，停止播报告知。 |

页面显示服务未配置时检查 `.env` 文件名、北京空间和运行目录。百炼建连返回 401/403 时核对密钥、空间与模型权限，429 时核对限流和额度。使用的是本机回环地址；浏览器会在点击开始时申请麦克风权限。

## 进度和证据

每次测试保存为独立的模拟申请办理会话。业务库位于 `data/review.sqlite`。坐席的播放回录、模型转写、工具结果、打断位置对应的回复和材料进度保存在本机。页面用通话凭据读取本次会话。浏览器在本地音频输出处截取每次坐席回复，后端结合回录的有效音量、完整转写中的材料要点和播放中断状态判断“待讲 / 已播部分 / 已播完整”。“已播完整”描述浏览器侧的播出情况，商家是否理解需另行询问。刷新或掉线时保留已持久化的进度，证据不足的要点会重新说明。原始示例 POP-DEMO-018 含两项模拟材料。当前可切换多张案卷。京麦正式沙箱、全量人工复核与赛方时延复测仍待完成。[完整架构](ARCHITECTURE.md)

## 开发验证

结果页保留尚未答完或缺少依据的追问。已核身商家明确要求来电时会留下本地回电待办，撤销请求会清除该待办。开发与留出案例分别列在 `cases/callback.json`，每条含核身条件、原话、预期动作和依据。运行 `npm run eval:callback` 可分别查看两组的正确数、应回电中的漏判数及其他案例中的误触发数。

需要复核时延时，可在接通前勾选「同时保存双方语音」。挂断后从结果页下载逐轮 JSON 和每次连接的 8 kHz WAV，左声道为商家、右声道为浏览器实际放行的坐席语音。JSON 用同一次连接的音频时钟记录断句事件、商家有效音量候选区间、坐席起声、打断停播、工具依据和模拟回执。用时间点减去该连接的 `recording.originMs` 即可定位录音中的毫秒位置。录音片段标记 `finished: false` 表示结尾缺少确认。回听后在导出的记录中填写 `confirmedSpeechEndMs` 和 `firstIntelligibleMs`，两者之差是该轮的 `firstWordLatencyMs`。空值保留为待核对。每次重连独立计时。

运行 `npm run eval:latency -- 通话A.json 通话B.json` 汇总已标注的导出文件，可只传一通。两个标注字段均使用连接音频时钟的毫秒值，从 WAV 读取的位置需加回 `recording.originMs`。输出包含逐轮差值、总体及调工具／未调工具轮次的 P50/P95（按升序取第 ⌈p×n⌉ 项）。开场、抢话和未配对轮次单列；`withoutTimedReply` 统计缺少坐席起声时间的轮次，可能与未配对计数重叠。可计分样本为零时分位数显示 `null`。

运行 `node --test --test-name-pattern "guidance replay" test/review.test.mjs` 可重放 16 条材料查询，复现商家问页码、模型误选授权链路等情形。[技术调研与本轮改动](ARCHITECTURE.md#2026-11-22-对照调研与改动)

`npm test` 覆盖核身门槛、材料查询、错号、播放证据、重复事件、重连和数据库重启，并检查转发给百炼的模型 ID。检测到 Chrome 或 Edge 时还会启动无界面浏览器，使用本地 WebRTC 对端、模拟麦克风和测试音频自动跑一通电话。可用 `CHROME_BIN` 指定浏览器可执行文件。自动化测试不消耗百炼额度；模型的实际听辨、音色和端到端时延需使用队内凭据联测。
